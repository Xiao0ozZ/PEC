# 工程架构

## 1. 分层原则

工程按“领域核心、运行时适配、界面应用”分层。正式平台只有 React 应用和原生 HTML 原型两种页面来源：

```text
packages/project-core          项目包、HTML、文档、路由和关联的领域规则
       ├─ packages/platform-server   独立 Node 本地服务（本机可写、局域网只读）
       ├─ packages/platform-mcp      本地 MCP Server（stdio 只读工具）
       ├─ plugins/                   Vite 开发接口、热更新与构建适配
       └─ scripts/project-cli.mjs   项目 CLI 入口

packages/platform-client       框架无关的浏览器请求与响应归一化
packages/platform-contracts    前后端共享的类型与接口契约
apps/platform-react/           React 正式平台、Ant Design、路由和浏览器状态
```

`packages/project-core` 不依赖 React、Vite、HTTP 或浏览器 API。它提供项目 Manifest、页面定义、HTML 原型扫描、Markdown 文档、PRD 关联、路由菜单管理、健康检查、路径边界和原子写入能力。平台服务、CLI、MCP 和 Vite 插件都调用这些共享领域函数，避免重复实现规则。

独立本地服务支持平台设置、项目配置、页面级 PRD 关联、组件级 PRD 关联和路由菜单的本机写入；服务监听局域网地址时，远程请求仍保持只读。`packages/platform-server/src/runtime.js` 负责启动预检、地址提示、监听错误归一化和退出生命周期。

## 2. 核心包职责

- `project-manifest.js`：项目 ID、客户端、入口、主题、资源和外部资料目录校验。
- `project-definitions.js`：HTML 页面定义、菜单分组、默认页面和页面文件校验。
- `html-prototypes.js`：递归扫描 HTML、读取页面 Manifest、生成稳定路由并处理内容区承载。
- `html-preflight.js`：检查 HTML5 基础结构、页面边界、相对链接、外部资源和主题变量。
- `route-management.js`：新增、编辑、删除、排序、分组修改以及备份还原 HTML 路由。
- `project-management.js`：项目包初始化和项目基础资料更新。
- `ai-context.js`：项目、页面、文档和 PRD 关联的确定性上下文与追溯报告。
- `schema-migration.js`：项目 Manifest Schema 版本扫描、差异预览、备份和原子升级。

机器可读契约位于 `packages/project-core/schemas`。JSON Schema 供编辑器和外部工具使用，运行时还会检查跨字段关系和本地文件是否存在。

## 3. 插件职责

- `project-packages-plugin`：项目发现、项目资料读取、热更新和构建资产输出。
- `html-prototype-plugin`：HTML 原型扫描结果、内容区注入、开发读取和构建复制。
- `prd-content-plugin`：PRD 读取、变更通知和构建快照。
- `project-routes-plugin`：路由菜单管理的开发接口适配。
- `platform-settings-plugin`：当前服务实例的开发模式配置。

插件只负责 Vite 或 HTTP 适配，不重新定义项目包 Schema，也不直接维护业务页面状态。

## 4. 页面来源和运行链路

```text
项目包 project.json / page-definitions.js / html-pages / prototype / docs
                              │
                              ▼
                    packages/project-core
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
           Vite 开发        Node 服务         MCP / CLI
              │               │               │
              └───────────────┼───────────────┘
                              ▼
                    apps/platform-react
                  React 外壳 + HTML 承载
```

托管 HTML 放在 `html-pages/{client-id}`，外部 HTML 由 `prototype.clients` 扫描。两者都会转换为统一的页面目录，React 外壳负责路由、菜单、主题、PRD 对照和页面容器；原始 HTML 负责业务内容和页面内交互。

## 5. CLI

```powershell
npm run project -- help
npm run project -- validate
npm run project -- health
npm run project -- preflight --file D:\prototypes\page.html
npm run project -- mount --project sample --docs D:\product\docs --prototype admin=D:\product\html
npm run project -- snapshot --project sample
npm run project -- trace --project sample
npm run project -- build-review --base /review/
npm run project -- serve --host 127.0.0.1 --port 5188
```

CLI 默认只读源项目；挂载、快照和追溯输出写入明确的本地配置或输出目录。需要修改项目配置时使用项目管理页或项目包自身的工程流程。

## 6. 设计与维护边界

- React 公共页面、顶栏、侧栏、主题和组件只在 `apps/platform-react` 维护。
- Ant Design 的组件尺寸、颜色、圆角和状态优先使用 `ConfigProvider` token 与 `--app-*` 语义变量。
- HTML 原型只使用模板定义的编辑区域和 `--app-*` 主题变量，不复制平台外壳。
- 项目业务字段、模拟数据、资源和 PRD 留在项目包或挂载目录中。
- MCP 只提供结构化只读上下文，不监听网络端口，也不直接修改项目文件。
- 新的跨项目能力必须先沉淀到 `project-core` 或平台公共组件，再由页面调用。

## 7. 验证

```powershell
npm run typecheck
npm run lint
npm run test:unit
npm run audit:projects
npm run build
```

浏览器行为需要另外执行 `npm run test:smoke`。静态检查、单元测试和构建通过，只能证明对应层级的正确性，不能替代浏览器验收或真实业务接口验收。
