# 可插拔项目包指南

## 1. 定位

工程由共用平台外壳和独立项目包组成。平台负责首页、项目入口、登录框架、顶栏、侧栏、主题、文档阅读、路由菜单和 HTML 页面承载；项目包负责自己的名称、品牌资源、客户端入口、HTML 页面、模拟数据、文档和移动端内容。

项目包之间不共享业务页面或业务数据，平台也不硬编码具体项目的业务入口。当前工程是前端原型平台，不连接真实业务后端。

## 2. 目录规范

```text
projects/{project-id}/
├─ project.json                 项目 Manifest
├─ page-definitions.js          客户端、菜单和 HTML 页面登记
├─ .platform/
│  ├─ page-prd-links.json       页面级 PRD 关联
│  ├─ prd-bindings.json         组件级 PRD 关联
│  └─ route-order.json          菜单和页面排序
├─ html-pages/{client-id}/      平台管理的 HTML 页面
├─ assets/                      Logo、登录背景和项目图片
├─ data/                        可选的项目级模拟数据
├─ docs/                        可选的项目文档
├─ prototype/                   可选的外部 HTML 原型目录
└─ mobile/                      可选的移动端静态演示
```

`project-id`、项目文件夹名和 `project.json.id` 必须完全一致，并使用小写 kebab-case。可复制 `templates/project-package` 作为新项目起点，或运行：

```powershell
npm run project -- init --id sample-project --name "示例项目"
npm run audit:projects
```

脱敏样例可以安装到被 Git 忽略的本地目录：

```powershell
npm run project:example
```

## 3. project.json

常用字段如下：

| 字段                     | 说明                                   |
| ------------------------ | -------------------------------------- |
| `schemaVersion`          | 当前固定为 `1`                         |
| `id`                     | 项目唯一标识，必须与文件夹名一致       |
| `name`、`shortName`      | 项目全名和简称                         |
| `description`、`version` | 首页说明和项目包版本                   |
| `pageDefinitions`        | 固定为 `page-definitions.js`           |
| `branding`               | `logo`、`favicon` 等项目内资源路径     |
| `theme`                  | 主色、悬停色、按下色和页面背景色       |
| `clients`                | 客户端名称、默认页、进入方式和页面外壳 |
| `entries`                | 首页展示的客户端、文档和移动端入口     |
| `docs`                   | 文档中心开关和文档目录                 |
| `prototype`              | 外部 HTML 原型扫描开关和目录           |
| `mobile`                 | 移动端入口开关和静态 HTML 路径         |
| `features`               | 项目级能力开关，仅登记实际存在的能力   |

客户端示例：

```json
{
  "id": "admin",
  "name": "管理端",
  "defaultPage": "home",
  "entry": { "mode": "direct" },
  "layout": { "type": "sidebar" }
}
```

`entry.mode` 支持 `direct`、`platform-login` 和 `custom-page`。`layout.type` 支持 `sidebar`、`topnav`、`none` 和 `bare`。页面外壳、主题和入口由平台统一渲染，业务 HTML 不应自行复制平台菜单。

## 4. 页面定义

`page-definitions.js` 导出 `clientPageDefinitions`，每个客户端维护：

- `sections`：菜单分组及顺序；
- `pages`：路由片段、页面名称、标题、HTML 来源、分组和图标。

页面来源只允许两种：

- `html-template`：项目包内 `html-pages/{client-id}` 的托管 HTML；
- `html-direct`：由 `prototype` 目录扫描得到的外部 HTML。

示例：

```js
export const clientPageDefinitions = {
  admin: {
    sections: [{ id: 'workspace', title: '工作区' }],
    pages: [
      {
        path: 'home',
        name: 'admin-home',
        title: '首页',
        sourceType: 'html-template',
        source: 'home.html',
        section: 'workspace',
        icon: 'House',
      },
    ],
  },
};
```

页面路由统一为：

```text
/p/{project-id}/{client-id}/login
/p/{project-id}/{client-id}/{page-path}
```

新增托管页面时，复制 `templates/html-prototype-page.html` 到对应的 `html-pages/{client-id}`，修改页面内容和 Manifest，再在 `page-definitions.js` 或“路由菜单管理”中登记。模板使用原生 HTML、CSS 和浏览器 API，可独立打开，也能由 React 外壳承载。

## 5. 外部 HTML 原型

在 `project.json` 中启用 `prototype` 后，平台会递归扫描配置的 HTML 目录，根据页面 Manifest、标题和相对路径生成页面目录。模板化 HTML 默认只承载 `data-page-content` 内容区；完整外壳页面可设置对应来源的 `shellMode` 为 `full`。

外部目录可以是项目包内相对路径，也可以是本机绝对路径。平台只读取外部源文件，不复制、不修改原文件；生产构建会生成本次发布的只读快照。

## 6. 文档中心

`docs.enabled=true` 后，文档中心扫描 `docs.root` 下的 Markdown，并按文件夹生成左侧分类，只显示文件名。支持 Markdown、Mermaid、相对图片和相对文档链接。`docs.root` 可以是项目包内目录，也可以是本机绝对路径；外部文档只读。

页面级关联保存在 `.platform/page-prd-links.json`，组件级关联保存在 `.platform/prd-bindings.json`。关联修改只在本机开发服务开放，局域网访问保持只读。

## 7. 项目管理与路由管理

项目管理页可以新建和编辑项目资料、客户端入口、文档入口、移动端入口、主题和首页显示状态。项目 ID 创建后不可修改；已有业务 HTML、模拟数据和文档不会被管理页重写。

路由菜单管理页可以按客户端新增、编辑、删除和排序 HTML 路由，也可以新增、重命名和排序菜单分组。页面文件改名、删除和分组调整会在项目包的 `.backups` 中留下可还原记录；外部 HTML 只能回到原型目录维护。

## 8. 外部资料挂载

完整项目包或仅文档、原型目录都可以挂载到本机绝对路径：

```powershell
npm run project -- mount --project sample --docs D:\product\docs
npm run project -- mount --project sample --prototype admin=D:\product\html
npm run project -- mount --project sample --clear-docs --clear-prototype admin
npm run project -- mounts
```

挂载记录保存在被 Git 忽略的 `project-mounts.local.json`。取消挂载只删除本机记录，不删除外部文件。项目扫描、文档中心、HTML 原型、健康检查和构建使用同一套挂载解析规则。

## 9. 本地运行和边界

```powershell
npm install
npm run dev
npm run serve:local -- --host 0.0.0.0 --port 5188
```

Windows 双击 `启动React开发环境.cmd` 会同时启动 5188 的 React 开发服务和 8080 的局域网服务。写接口只允许本机；局域网访问者可以查看项目、HTML、PRD、路由和健康报告，但不能修改源资料。

新增项目包或配置后，开发服务会通过 Vite 重新扫描；生产环境需要重新执行 `npm run build` 并发布新的 `dist` 快照。

## 10. 校验

```powershell
npm run audit:projects
npm run project -- health
npm run project -- preflight --file D:\prototypes\page.html
npm run typecheck
npm run lint
npm run test:unit
npm run build
```

HTML 模板至少要保留一个 `data-page-content`、一个 `data-business-content`、页面 Manifest，以及 `PAGE_CONTENT`、`PAGE_OVERLAYS`、`PAGE_LOGIC` 编辑边界。详细模板规则见 [HTML 原型创建提示词](./HTML原型创建提示词.md)。
