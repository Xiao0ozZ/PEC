## 1. 迁移结论

本次工作只迁移共用 Web 平台，不引入 Electron，也不改变项目包的业务资料。

目标架构：

```text
项目包、HTML、PRD、Mock、资源、关联配置（保持协议稳定）
                           ↓
packages/project-core + Vite plugins（复用并逐步类型化）
                           ↓
React + TypeScript 平台应用
                           ↓
Ant Design 单一组件与设计系统
```

迁移采用“新 React 应用并行建设、按业务闭环替换、最后切换入口”的方式。禁止在现有 Vue 文件中逐个机械改写，也禁止一次性删除 Vue 版本后再补功能。

## 2. 硬性边界

### 2.1 保持不变

- `projects/{project-id}` 项目包目录结构和现有配置协议。
- 项目包中的 HTML 原型、Markdown PRD、Mock、资源、移动端内容和关联配置。
- `packages/project-core` 的领域规则与纯 Node 文件能力。
- Vite 插件提供的项目扫描、HTML 读取、PRD 读取、页面导入导出、路由编辑和平台设置接口；允许重构实现，但接口行为必须先锁定。
- 当前正式 URL 结构，例如 `/`、`/components`、`/tools/*`、`/p/{projectId}/{clientId}/*`。
- `projects/` 继续保持 Git 忽略，不因迁移加入暂存区。

### 2.2 本次迁移范围

- 首页、控制台、组件规范、项目包管理、页面导入导出、路由菜单管理、AI 上下文页。
- 客户端外壳、登录页、移动端承载页、HTML 原型承载页和系统状态页。
- 文档中心、PRD 阅读侧窗、页面级与功能级 PRD 关联。
- 公共组件、主题、多语言、路由、浏览器状态和前端数据访问层。
- 单元测试、端到端测试、质量脚本和开发文档。

### 2.3 明确不做

- 不把项目包中的独立 HTML 改成 React。
- 不重写 PRD 或修改项目专属业务内容。
- 不在迁移过程中增加 Electron、云同步、账号体系等新产品范围。
- 不为了 React 迁移同时改变项目包 Schema；确有必要时必须单独提案和提供迁移器。
- 不混用其他 React 组件库；除非用户后续明确提出并重新确认迁移范围。
- 首页使用 Ant Design 统一重写视觉与布局；项目选择、浏览器记忆、入口、管理工具快捷键和访问规则保持兼容。
- 公共管理页（控制台、组件规范、项目包管理、导入导出、路由菜单管理、AI 上下文）及其弹窗，保留功能、信息层级、文案、状态和交互路径，但允许使用 Ant Design 重新组织视觉和控件密度；不得借此修改项目包协议或业务页面。
- 未在 Vue 页面或明确需求中定义的业务行为，不自行补充；确有兼容需要时先记录差异，等待用户确认。

## 3. 技术栈决策

| 领域       | 决策                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| 应用框架   | React + TypeScript，启用严格类型检查                                               |
| 构建       | 保留 Vite，新增 React 应用入口；Vue 入口在迁移期继续可运行                         |
| 路由       | React Router，保持现有 URL、重定向和隐藏项目访问规则                               |
| 组件库     | 只使用 Ant Design，覆盖布局、导航、表单、表格、弹窗、抽屉、反馈和数据展示          |
| 图标       | 只使用 `@ant-design/icons` 作为 React 平台图标来源；业务 HTML 原型自身图标不受影响 |
| 服务端状态 | TanStack Query，用于项目、文档、路由、导入导出等接口状态和缓存失效                 |
| 应用状态   | 优先组件状态与 Context；跨页面持久 UI 状态使用轻量 Store，不默认引入 Redux         |
| 多语言     | `react-i18next`，复用现有语言目录和默认简体中文规则                                |
| Markdown   | 复用 `markdown-it`、DOMPurify、Mermaid 的现有处理规则，封装为 React 组件           |
| 图表       | 复用 ECharts，建立 React 生命周期适配组件                                          |
| 样式       | 平台 Token + CSS Variables + CSS Modules；项目主题与平台固定主题分域               |
| 测试       | Vitest + React Testing Library + Playwright；复用现有领域测试与 E2E 场景           |

React 与 TypeScript 版本在阶段 2 开始时锁定为当时的稳定兼容组合，不在计划文档中追随浮动最新版。

## 4. Ant Design 治理规则

### 4.1 默认规则

- 业务页面只从平台公共 UI 层导入组件，不在页面内散落 Ant Design 直接依赖。
- 公共 UI 层优先封装 Ant Design，并统一尺寸、圆角、密度、空状态、反馈和表单校验行为。
- 不安装、不导入、不预留 Arco Design 适配层。
- 同一个交互族只能有一个实现，例如全平台只能有一种基础 Button、Modal、Select 和 Table。
- React 平台不得混用其他组件库的同类控件。

### 4.2 其他组件库的变更条件

当前迁移计划不允许自行采用 Arco Design 或其他 React 组件库。只有用户后续明确提出时，才先更新本计划、说明使用范围和维护影响，并在获得确认后实施；不得因单个页面的视觉偏好自行引入。

### 4.3 主题边界

- 首页选中项目后，项目品牌信息和项目入口可读取项目主题色。
- 客户端壳和项目业务页按项目主题色展示。
- 控制台、组件规范、项目包管理、导入导出和路由管理等平台公共页固定使用平台蓝色主题，不随项目切换。
- Ant Design Token、平台 CSS Variables 和 HTML 原型注入变量必须有明确映射，禁止页面内散落近似色值。

## 5. 目标目录结构

迁移期建议建立并行应用，避免污染当前 Vue 入口：

```text
apps/
└─ platform-react/
   ├─ src/
   │  ├─ app/                 应用入口、Provider、错误边界
   │  ├─ routes/              React Router 路由与访问守卫
   │  ├─ pages/               平台页面
   │  ├─ features/            项目、文档、PRD、路由、导入导出等业务闭环
   │  ├─ ui/
   │  │  ├─ ant/              Ant 基础适配
   │  │  └─ platform/         平台语义组件
   │  ├─ data/                Repository、Query 与 DTO
   │  ├─ state/               少量跨页 UI 状态
   │  ├─ i18n/
   │  ├─ styles/
   │  └─ test/
   └─ vite.config.ts

packages/
├─ project-core/              继续保持框架无关
├─ platform-contracts/        新增：API DTO、项目包前端类型、错误模型
└─ platform-client/           新增：框架无关的数据访问层

src/                          迁移期间保留的 Vue 平台；阶段 8 后删除
```

## 6. 分阶段执行计划

### 阶段 0：确定迁移基线

目标：先得到一份可复现、可回退的 Vue 基线。

任务：

- 审核并处理当前未提交修改，保证迁移从来源明确的工作区开始。
- 记录当前 Node、npm、Vite、Vue、插件和测试版本。
- 运行并记录 `lint:core`、单元测试、项目校验和生产构建结果。
- 建立 React 迁移分支，不在 `main` 上进行大规模框架迁移。
- 保存主要路由、接口响应和代表性页面的基准清单；视觉基准需获得浏览器验证授权后采集。
- 清点项目包中仍依赖 Vue SFC 的页面，形成兼容迁移列表，但不修改项目资料。

交付物：

- 可回退的 Git 基线提交或标签。
- 当前功能、路由、接口、测试和已知问题清单。
- Vue SFC 项目页面兼容清单。

验收门槛：

- 工作区无来源不明的修改。
- 基线可以安装、启动和构建。
- 后续任一阶段都可切回 Vue 入口。

预计工作量：S。

### 阶段 1：锁定框架无关契约

目标：先把真正需要保留的业务规则从 Vue 用法中隔离出来。

任务：

- 为项目、客户端、入口、路由、文档、PRD 关联、HTML 页面、备份和平台设置建立 TypeScript 类型。
- 新建 `platform-contracts` 与 `platform-client`，统一封装现有 `fetch` 接口。
- 将错误统一为可判断的错误码，不让 React 页面解析中文错误文案。
- 为 Vite 虚拟模块 `virtual:project-html-pages` 增加框架无关的稳定输出类型。
- 锁定以下接口行为：项目扫描、Manifest 读写、HTML 扫描、PRD 读取、路由增删改排、导入导出、项目设置和关联配置。
- 用契约测试记录正常、空、错误、无权限、路径不存在和非法路径场景。

交付物：

- 框架无关类型与数据访问 SDK。
- 接口契约测试和错误码表。

验收门槛：

- Vue 应用可以先改用新数据访问层且行为不变。
- React 页面不需要直接访问 Vite 插件内部实现。
- `packages/project-core` 仍不依赖 React、Vue、Vite 或浏览器 API。

预计工作量：M。

### 阶段 2：建立 React 基础应用与设计系统

目标：建立能独立启动、构建和测试的 React 平台骨架。

任务：

- 创建 Vite + React + TypeScript 严格模式应用。
- 接入 React Router、TanStack Query、错误边界、多语言和测试环境。
- 接入 Ant Design 的 ConfigProvider、Locale、主题 Token、弹层容器和消息入口。
- 建立平台公共组件：页面布局、页面头、内容面板、统计项、筛选栏、数据表、状态标签、空状态、表单弹窗、确认弹窗和分页。
- 建立公共页面固定蓝色主题与项目主题的分域 Provider。
- 完成 Ant 组件适配规则；不安装或预留其他组件库。
- 新增 `dev:react`、`build:react`、`lint:react`、`typecheck:react`、`test:react` 等命令，不替换现有 Vue 命令。

首批样板页：

- 组件规范页：验证公共组件和状态覆盖。
- 项目包列表只读页：验证表格、筛选、状态和主题。
- 项目配置弹窗只读样板：验证复杂表单与弹窗布局。

验收门槛：

- React 应用可独立启动和生产构建。
- TypeScript 严格检查、lint、单元测试通过。
- 同类控件只有一种平台语义实现。
- 样板页可确认 Ant 为主的视觉方向。

预计工作量：M。

### 阶段 3：迁移平台入口与只读浏览闭环

目标：先让用户能在 React 平台完整浏览项目，不做高风险写入。

迁移顺序：

1. 首页与项目选择记忆；
2. 客户端入口与隐藏项目访问拦截；
3. 客户端外壳、顶部导航、侧栏折叠和账户菜单；
4. HTML 原型直读与内容区模式；
5. 移动端承载页；
6. 文档中心；
7. PRD 固定分屏、浮层、目录导航和页面关联跳转；
8. 系统空状态、不可用页和 404。

关键要求：

- 外部 HTML 继续由同源 iframe 或现有稳定机制运行，不将其转换为 React。
- HTML 自身的脚本、弹窗、图表、参数链接和相对资源必须保持可用。
- 文档中心保持左侧文件目录、中间阅读、右侧本文目录结构。
- PRD 面板行为、拖动、定位和关联配置不能因框架迁移退化。
- 旧 URL 必须跳到相同内容，浏览器刷新后状态可恢复。

验收门槛：

- 代表性项目可以从首页进入所有客户端、HTML 页面和文档。
- 隐藏项目不能通过直链访问。
- 现有 PRD 页面级和功能级关联可以查看和定位。
- Vue 与 React 对同一项目包的只读结果一致。

预计工作量：L。

### 阶段 4：迁移平台管理闭环

目标：迁移会写入配置或改变项目状态的管理功能。

迁移顺序：

1. 控制台与开发工具显示开关；
2. 项目包管理；
3. 新建与编辑项目弹窗；
4. 客户端显示、项目显示、主题色、HTML 来源和 PRD 目录配置；
5. 路由与菜单分组、顺序、页面级 PRD 关联；
6. 页面与功能 PRD 绑定管理；
7. AI 上下文查看与导出。

关键要求：

- 所有写操作使用统一 Mutation、确认、成功、错误和缓存失效策略。
- 保存前后使用 Schema 校验；失败不得留下半写状态。
- 分组排序和菜单排序结果与实际客户端所见一致。
- 项目配置弹窗保持固定尺寸、内容可滚动、底部操作稳定。

验收门槛：

- React 完成创建、编辑、隐藏、显示、排序、关联和恢复后，Vue 读取结果一致。
- 原子写入、备份、路径安全和错误恢复测试通过。
- 不修改 `projects/` 中未被当前操作明确选中的资料。

预计工作量：L。

### 阶段 5：重构导入、回导、导出和页面运行模型

目标：解决当前最强的框架耦合点，让页面资产不再依赖 Vue SFC 才能运行。

目标页面类型：

| 页面类型        | React 平台处理方式                                                       |
| --------------- | ------------------------------------------------------------------------ |
| `html-template` | 默认推荐；保存 HTML 与页面描述，React 使用 HTML 原型运行时承载           |
| `html-direct`   | 直接扫描外部文件夹，保持原文件不变，React 只读取和显示                   |
| `react-module`  | 高级工程页面，由项目明确提供 TSX 模块                                    |
| 旧 `vue-sfc`    | 不自动迁移；当前登记的 8 个未使用页面已由用户明确排除在 React 迁移范围外 |

任务：

- 将“HTML 导入”默认结果改为框架无关的 HTML 模板页面登记，不再生成新的 Vue 页面。
- 保留导入、导出、修改后回导和 HTML 直读闭环。
- 保证导出 HTML 是独立、规范、轻量、可编辑、可再次导入的正式 HTML。
- 保持导出页面间链接、查询参数、标题、副标题、弹窗、交互和项目主题变量。
- 提供旧 Vue SFC 页面清点和转换工具；转换必须显式执行并保留备份。
- 更新页面生成器、模板和测试，使新生成的工程页面默认面向 React 或框架无关运行时。

验收门槛：

- 导入 → React 平台运行 → 导出 → 修改 → 回导 → 直读形成稳定回环。
- 全选导出与单页导出的页面内容、体积、编码和链接行为一致。
- 没有仍被使用的 Vue SFC 页面被静默跳过。
- 项目包中的原始 HTML 和 PRD 不因读取动作被修改。

预计工作量：XL；这是全迁移风险最高阶段，必须单独验收。

### 阶段 6：双版本一致性回归

目标：在切换正式入口前，证明 React 不是“看起来差不多”，而是功能等价。

任务：

- 建立 Vue/React 路由映射和场景矩阵。
- 对首页、客户端、文档、PRD、项目管理、路由、导入导出和错误页逐项对照。
- 复用 14 组现有单元测试并补 React 组件与 Hook 测试。
- 复用 4 组现有 E2E 流程，增加项目隐藏、刷新恢复、PRD 定位、路由排序和导入导出回环。
- 进行性能基准：首次加载、项目切换、大目录扫描后渲染、PRD 打开和侧窗切换。
- 进行无障碍、键盘、焦点、弹层、滚动和 reduced-motion 检查。

验收门槛：

- P0/P1 功能差异为 0。
- 自动化测试、lint、类型检查、项目校验和生产构建全部通过。
- 关键交互没有可感知的性能退化。
- 浏览器视觉与交互验收仅在获得明确授权后执行并留存结果。

预计工作量：L。

### 阶段 7：切换正式入口与观察期

目标：React 成为正式平台，并移除旧 Vue 平台入口。

状态：已完成。默认开发、正式本地服务、生产构建和 CI 均以 React 为正式入口；旧 Vue 平台入口已删除。浏览器视觉验收仍按项目约束未执行。

任务：

- 将 `/` 和正式构建入口切换到 React。

## 8. 风险与控制

| 风险                      | 后果                                   | 控制措施                                                      |
| ------------------------- | -------------------------------------- | ------------------------------------------------------------- |
| 把迁移理解为语法翻译      | 保留原有耦合和卡顿，React 只换了外壳   | 阶段 1 先抽契约和数据访问层                                   |
| 混用多个组件库            | 视觉、交互、样式、包体积和维护成本失控 | React 平台只使用 Ant Design；其他组件库必须由用户另行明确授权 |
| 现有 Vue 项目页面无法运行 | React 切换后部分项目页面丢失           | 阶段 0 清点，阶段 5 显式转换，阶段 8 前禁止删除 Vue 运行时    |
| Vite 插件接口随页面一起改 | 导入、路由和文档功能同时失效           | 先做契约测试，保持 API 行为兼容                               |
| 双版本长期并存            | 修改两套代码，维护成本翻倍             | 只允许迁移期并存，每阶段有明确退出条件                        |
| 项目主题污染公共页        | 管理页面颜色随项目变化                 | 建立平台与项目双 Theme Provider                               |
| 一次性切换                | 问题难定位且无法快速回退               | 并行应用、功能闭环迁移和入口开关                              |
| 借迁移增加新功能          | 范围失控，无法判断迁移是否成功         | 迁移期默认只做功能等价，新增需求单独排期                      |
