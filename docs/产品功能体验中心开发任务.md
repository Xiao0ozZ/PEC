# 产品功能体验中心开发任务

## 当前目标

维护一个以 React + Ant Design 为平台底座、以原生 HTML 为业务原型来源的本地项目资料平台。平台用于产品评审、业务演示和前端开发协作，不连接真实业务后端。

## 已确认的架构边界

- `apps/platform-react` 是唯一的平台应用入口。
- `packages/project-core` 是项目包、HTML 原型、文档、路由和关联规则的共享领域核心。
- `packages/platform-client` 负责浏览器端请求和响应归一化。
- `packages/platform-contracts` 负责前后端共享契约。
- `packages/platform-server` 提供独立 Node 服务，本机可写、局域网只读。
- `packages/platform-mcp` 提供本地 stdio 只读上下文工具。
- `plugins/` 只做 Vite 开发、构建和接口适配，不重复实现领域规则。
- 项目业务页面只使用 `html-template` 或 `html-direct` 两种 HTML 来源。

## 功能范围

### 平台外壳

- 首页、项目和客户端入口；
- 顶栏、侧栏、主题、响应式布局和统一 Ant Design token；
- React 公共页面、路由、菜单和开发模式；
- HTML 原型内容区承载、主题桥接和滚动处理。

### 项目资料

- 项目 Manifest、客户端和入口校验；
- HTML 页面目录扫描和路由菜单管理；
- Markdown 文档中心、目录分类、搜索、Mermaid 和相对资源；
- 页面级 PRD 关联、组件级关联和 AI 上下文；
- 本地目录挂载、健康检查、Schema 版本检查和原子写入。

业务原型如果需要进入 React 运行时，应另立 React 页面实现任务，使用 `apps/platform-react` 的公共组件和主题 token。

## 维护规则

1. 修改前先检查 `git status`、项目包范围和实际引用，保留用户已有的未提交修改。
2. 跨页面的颜色、字号、圆角、阴影和控件尺寸优先接入 Ant Design `ConfigProvider` token 或 `--app-*` 语义变量。
3. 项目业务字段、模拟数据、资源和 PRD 不写入平台公共壳。
4. HTML 原型不复制平台顶栏和侧栏；需要独立预览时使用模板提供的原生 HTML 外壳。
5. 文件删除必须基于实际引用、Git 状态和目录边界确认，不用批量清理替代逐项判断。
6. 修改完成后分别验证静态检查、单元测试、构建和浏览器行为；不把其中一项的通过扩大解释为全部验收。

## 常用验收

```powershell
npm run typecheck
npm run lint
npm run test:unit
npm run audit:projects
npm run build
npm run test:smoke
git diff --check
```

HTML 页面可单独检查：

```powershell
npm run project -- preflight --file D:\prototypes\page.html
```

Windows 双击 `启动React开发环境.cmd` 会同时启动 React 开发服务和局域网服务；该脚本属于开发环境基础设施，不能在清理临时文件时删除。
