## 1. 文档定位

本文定义营运端会员资质认证审核页面、审核提交规则、审核结果处理和数据记录要求。

关联原型：`02_原型和PRD/原型/营运端/member_review.html`

关联页面：营运端 / 客户中心 / 资质认证审核

## 2. 功能目标

1. 营运人员在一个页面内查看会员资料、证件资料、信用卡资料和历史审核记录。
2. 基本资料、身份证、驾驶执照、手持证件自拍统一在一个弹窗内提交审核结果。
3. 兼容旧版不通过类型和高风险不可复审能力，不要求管理员重复填写相同信息。
4. 驾驶执照审核通过时同步确定会员可用载具类型，供预约查询和创建订单校验。

## 3. 使用角色与权限

| 角色 | 权限 |
| --- | --- |
| 具备会员审核权限的营运人员 | 查看待审核及已驳回会员、查看审核详情、提交单人审核、执行批量审核。 |
| 无会员审核权限的营运人员 | 不展示审核操作入口，不允许调用审核提交接口。 |

高风险不可复审属于单人审核操作，不允许通过批量审核执行。

## 4. 页面结构

### 4.1 审核列表

列表支持按会员姓名或手机号、审核状态、注册渠道、提交时间筛选。

列表至少展示：

| 字段 | 说明 |
| --- | --- |
| 用户 ID | 会员唯一标识。 |
| 姓名 | 会员姓名。 |
| 手机号 | 会员注册手机号，不脱敏展示。 |
| 渠道 | iOS APP、Android APP、Web 官网。 |
| 提交时间 | 本次审核申请提交时间。 |
| 等待时长 | 当前时间减本次提交时间。 |
| 状态 | 待审核、已驳回、高风险。 |
| 操作 | 普通待审核或已驳回会员显示“审核”；高风险会员显示“不可复审”。 |

普通已驳回会员允许再次进入审核；高风险会员不允许选择、批量审核或再次进入审核。

### 4.2 审核详情侧窗

侧窗按以下顺序展示：

1. 基本资料：身份信息、联系与账户、地址信息、紧急联系人。
2. 身份证：身份证正面、反面。
3. 驾驶执照：驾照类型、签发地、号码、有效日期、正面、反面。
4. 手持证件自拍：手持身份证自拍、其他证件照。
5. 信用卡资料：信用卡名称、持卡人姓名、遮罩卡号、有效期限、是否默认，只读展示。
6. 审核历史：时间、结果、审核说明、审核人，记录较多时表格内部滚动。

信用卡资料和其他证件照只用于资料核对，不作为独立审核项。

## 5. 提交审核弹窗

### 5.1 审核项

弹窗固定展示以下四项：

1. 基本资料。
2. 身份证。
3. 驾驶执照。
4. 手持证件自拍。

打开弹窗时，四项默认选中“通过”。管理员可以将任意一项改为“不通过”。

### 5.2 不通过原因

1. 选择“不通过”后，必须填写该项驳回原因。
2. 驳回原因控件支持选择系统预设原因，也支持直接输入新的原因。
3. 选择和输入共用同一字段，不另设补充说明或备注输入框。
4. 手动输入内容去除前后空格后不得为空。
5. 多项不通过时，每项分别保存对应原因。

预设原因由前端按审核项展示，后端保存最终原因文本，不得只保存预设选项序号。

### 5.3 旧版不通过类型映射

| 当前审核项 | 自动生成的旧版不通过类型 |
| --- | --- |
| 基本资料不通过 | 会员基本资料错误 |
| 身份证不通过 | 身份证资料错误 |
| 驾驶执照不通过 | 驾驶执照资料错误 |
| 手持证件自拍不通过 | 自拍照资料错误 |

管理员不需要再次选择不通过类型。多项不通过时，同时保存多个不通过类型。

### 5.4 用户可用载具类型

1. 可选类型包括汽车、摩托车、微电车。
2. 驾驶执照审核通过时，必须至少选择一个可用载具类型；基本资料、身份证或手持证件自拍不通过不影响该字段选择。
3. 驾驶执照审核通过时，将选择结果写入会员资料。即使其他资料不通过、整体审核结果为驳回，也仍更新该字段。
4. 只有驾驶执照审核不通过时，可用载具类型不可编辑，本次不更新该字段并保留原值。
5. 微电车默认不要求驾照；汽车和摩托车仍按驾照资料和审核结果判断。

### 5.5 高风险不可复审

1. 仅单人审核且存在任一不通过项时，展示“高风险用户，不再提供复审”。
2. 勾选后提交必须进行二次确认，确认文案需明确提交后不再提供复审。
3. 提交成功后，会员同时记录审核驳回和高风险不可复审标记。
4. 高风险会员不允许重新提交审核申请，不允许营运人员再次审核。
5. 批量审核不展示高风险选项，不允许通过接口批量设置高风险不可复审。

## 6. 审核结果规则

| 条件 | 整体结果 | 可用载具类型 | 后续复审 |
| --- | --- | --- | --- |
| 四项全部通过 | 审核通过 | 写入本次选择 | 不适用 |
| 基本资料、身份证或手持证件自拍不通过，驾驶执照通过 | 审核驳回 | 写入本次选择 | 未勾选高风险时允许重新提交 |
| 驾驶执照不通过 | 审核驳回 | 不更新，保留原值 | 未勾选高风险时允许重新提交 |
| 任一项不通过并勾选高风险 | 审核驳回并标记高风险 | 按驾驶执照结果决定是否更新 | 不允许重新提交或再次审核 |

整体审核结果由四项结果自动计算，不提供独立的整体“通过 / 不通过”选择。

### 6.1 旧后端流程兼容

1. 四项资料全部通过时，提交原有“审核通过”后端流程。
2. 任一资料不通过时，提交原有“审核不通过”后端流程，并沿用旧版不通过类型、驳回原因和高风险标记。
3. 不新增第三种整体审核状态，不因可用载具类型是否更新改变审核流程分支。
4. 驾驶执照通过时，系统在原审核流程完成时同步更新可用载具类型；驾驶执照不通过时不提交该字段变更。

## 7. 批量审核

1. 只有待审核和普通已驳回会员可以加入批量审核，高风险会员不可选择。
2. 批量审核复用单人审核的四项结果、驳回原因和可用载具类型规则。
3. 打开批量审核弹窗时，四项默认选中“通过”。
4. 本次选择的四项结果、原因和可用载具类型统一应用到全部选中会员。
5. 任一资料不通过时，全部选中会员本次结果均为驳回；驾驶执照通过时仍统一更新可用载具类型，驾驶执照不通过时保留各会员原值。
6. 批量审核不支持高风险不可复审。

## 8. 审核历史

每次提交必须新增一条审核历史，不覆盖旧记录。至少记录：

| 字段 | 说明 |
| --- | --- |
| 审核时间 | 服务端提交成功时间。 |
| 整体结果 | 审核通过、审核驳回、审核驳回并标记高风险。 |
| 逐项结果 | 四项资料分别通过或不通过。 |
| 不通过类型 | 由不通过审核项自动生成，可多选保存。 |
| 驳回原因 | 每个不通过审核项对应的最终原因文本。 |
| 可用载具类型 | 记录本次是否更新及写入结果；驾驶执照通过时即使整体驳回也保存本次写入结果。 |
| 审核人 | 当前营运人员 ID 和姓名。 |

## 9. 后端校验

1. 四项审核结果必须完整。
2. 任一项不通过但未提供有效原因时拒绝提交。
3. 驾驶执照通过但未选择可用载具类型时拒绝提交。
4. 只有驾驶执照不通过时忽略前端提交的可用载具类型变更并保留数据库原值；驾驶执照通过时必须保存本次选择。
5. 不通过类型必须由后端按审核项再次生成，不信任前端直接传入结果。
6. 批量审核请求包含高风险标记时拒绝提交。
7. 会员已标记高风险不可复审时，拒绝新的审核申请和审核提交。
8. 审核状态、逐项结果、原因、可用载具类型变化和操作人必须在同一事务内提交。

## 10. 验收标准

1. 单人和批量审核打开时四项均默认选中“通过”。
2. 每项改为“不通过”后，可以选择预设原因或输入新原因。
3. 未填写不通过原因时不能提交。
4. 多项不通过时，系统保存多个类型和各自原因。
5. 四项全部通过时，系统只走原“审核通过”后端流程。
6. 任一项不通过时，系统只走原“审核不通过”后端流程；只有驾驶执照不通过时不更新可用载具类型。
7. 普通驳回会员可以重新提交并再次审核，历史记录完整保留。
8. 高风险驳回经过二次确认后不可再次提交或审核。
9. 批量审核不能设置高风险不可复审。
10. 信用卡资料、其他证件照和审核历史均可在详情侧窗查看。
