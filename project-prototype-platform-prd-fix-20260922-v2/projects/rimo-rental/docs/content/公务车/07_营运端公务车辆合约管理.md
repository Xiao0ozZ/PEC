## 1. 功能目标

营运人员在本页面建立和维护公务车合约，并可把来源合约下指定车辆改绑到同一企业的另一份合约。来源分公司配额保留，目标优先使用同一分公司的空闲配额，不足部分自动补配额，避免逐辆重新绑定。试用转正式属于车辆换约的一种场景，不单独建立一套转换逻辑。

对应原型：`02_原型和PRD/原型/营运端/official_vehicle_contracts.html`

## 2. 使用角色与权限

- 仅营运端具有“公务车辆合约管理”权限的用户可新增、编辑、删除、中止、撤销及执行合约转移。
- 企业端总公司管理员可建立、编辑、取消及执行本企业合约转移；分公司管理员无转移权限。详见《08_合约配额管理》。两端共用后端任务、预留和执行记录，不能重复占用容量。
- 所有新增、编辑、删除、转移、取消转移计划、中止和撤销操作必须记录操作人、操作时间、操作前数据和操作后数据。

## 3. 合约列表

列表展示合约编号与名称、实际用车企业、结算代付方、合约类型、计费方式、已绑定车辆数、合约金额、合约期间、生效时间、状态和操作。

合约金额只展示数字和千分位，不显示 `¥`、`￥` 或其他人民币符号。例如：`85,000.00 / 月`。

### 3.1 操作权限

| 合约状态 | 编辑 | 转移至其他合约 | 中止合约 | 撤销释放 | 删除合约 |
| --- | --- | --- | --- | --- | --- |
| 草稿 | 是 | 否 | 否 | 是 | 是 |
| 待客户支付 | 是 | 否 | 否 | 是 | 是 |
| 待生效 | 是 | 否 | 是 | 是 | 是 |
| 生效中 | 是 | 是 | 是 | 否 | 是 |
| 即将到期 | 是 | 是 | 是 | 否 | 否 |
| 已过期 | 否 | 仍有绑定车辆时允许 | 否 | 否 | 是 |
| 已终止 | 否 | 否 | 否 | 否 | 是 |
| 已作废 | 否 | 否 | 否 | 否 | 是 |

页面右上角新增“合约转移任务”，集中查看、新增、编辑和取消任务。合约“更多”仍保留“转移至其他合约”，自动带入来源合约；已有待执行任务时打开该任务编辑。两个入口共用同一转移弹窗，弹窗左下角提供“取消转移任务”。同一来源合约同一时间只允许存在一条待执行任务，可保留多条历史任务。

状态列第二行显示“有转出任务”“有转入任务”，仅表示存在待执行任务，不展示数量或执行时间。点击打开任务列表，并按该合约及转移方向筛选；有待执行任务的合约“更多”同时提供“查看转移任务”。执行失败后，原待执行提醒移除，改为“转移失败”，点击筛选该合约的失败任务；失败提醒持续至重新提交成功或取消。已完成、已取消任务不显示提醒。一个合约同时存在转入、转出或失败任务时，对应提醒可并存。

存在未执行转移计划时，来源和目标合约均不显示中止、撤销和删除入口，也不允许修改实际用车企业；用户必须先编辑或取消相关计划。操作权限表表达无转移计划时的基础权限。

### 3.2 删除合约

- 删除入口对草稿、待客户支付、待生效、生效中、已过期、已终止和已作废合约开放；即将到期合约仍须先中止后删除。
- 待生效合约删除后取消计划生效任务。生效中合约删除时，系统同步解除当前分公司配额和车辆绑定关系，再将合约从营运端及企业端隐藏。
- 合约存在未执行的来源转移计划，或正被其他来源合约的转移计划作为目标合约使用时，不允许删除；必须先取消对应计划并释放目标预留配额。
- 点击“删除合约”后必须弹出二次确认，明确显示合约编号，并提示“删除后该合约在营运端列表及企业端均不可见；历史订单、账单和操作记录仍会保留”。
- 用户确认后执行业务软删除。删除的合约不再进入营运端普通列表、企业端合约及配额列表，也不能再被新车辆绑定或用于新业务。
- 删除不物理清除合约数据，不改写历史订单、历史账单、历史车辆绑定和操作审计记录。

### 3.3 中止合约

- 待生效、生效中和即将到期合约均显示“中止合约”。
- 待生效合约中止后状态改为已终止，并取消计划生效任务。
- 生效中或即将到期合约中止后状态改为已终止，同步释放当前分公司配额及车辆绑定关系。
- 存在未执行转移计划时不允许中止，须先取消对应计划。

### 3.4 合约操作记录

页面右上角“新签合约”旁显示“操作记录”按钮。点击后以时间倒序查看全部公务车合约的操作流水，支持按合约编号或名称搜索，并可按操作类型筛选。

每条记录只展示操作时间、合约编号、合约名称、操作类型和操作人，不展示操作内容。记录范围包括新建、编辑、建立或修改转移计划、取消转移计划、立即转移、中止、撤销、删除及系统自动到期等操作。列表使用分页，默认每页5条。

立即转移执行成功后写入“立即转移”操作记录，并在任务列表保留“已完成”任务，不产生待执行提醒。任务列表用于任务管理，操作记录保留每次新增、修改、取消和执行的审计流水，两者不互相替代。

## 4. 合约编辑

### 4.1 可编辑资料

草稿、待客户支付、待生效、生效中和即将到期的合约均允许编辑。营运人员可修改全部人工录入资料，包括：

- 合约名称；
- 实际用车企业；
- 结算代付方及是否与实际用车企业相同；
- 合约类型；
- 总配额；
- 计费方式；
- 合约期数；
- 合约开始日期；
- 正式合约生效方式。

通过合约转移承接配额或车辆的合约同样适用上述规则。转移计划、实际转移结果及历史记录属于系统记录，不通过普通编辑功能修改。

### 4.2 不可直接编辑的系统记录

以下内容不属于人工录入资料，编辑弹窗只读展示或不提供输入入口：

- 合约编号；
- 已经写入的实际生效时间；
- 合约转移计划和转移记录；
- 实际转移时间、转移分公司数、转移配额数、转移车辆数及失败原因；
- 历史订单、历史账单、历史配额分配、历史车辆绑定和操作审计记录。

待生效合约尚未写入实际生效时间时，修改开始日期或生效方式后，系统重新计算计划生效时间和待生效状态。合约已经生效后，修改开始日期或生效方式不得回写或覆盖原实际生效时间；赠送期按“实际生效时间至最新合约开始日期”重新计算。

### 4.3 保存校验与影响

- `允许保存总配额 = 修改后总配额 >= 当前已绑定车辆数 AND 修改后总配额 >= 当前已分配配额 + 当前被转移计划预留配额`。不满足时阻止保存并提示最低可填配额。
- 合约新增、编辑均不提供单车计费单价输入。系统根据实际用车企业和计费方式读取企业价格配置中的对应单价。
- `合约金额 = 修改后总配额 × 实际用车企业对应计费周期的单车单价`，金额保留两位小数。企业未配置对应单价时阻止保存，并提示先完成企业价格配置。
- 合约期数必须大于或等于 1。生效中或即将到期合约调整后的结束日期不得早于当前日期。
- 合约开始日期或计费方式变化后，系统重新计算合约结束日期和合约金额。
- 修改实际用车企业后，该合约保存后的企业端可见范围、配额分配和新业务归属按新企业处理；已经创建的订单、账单及其企业资料仍使用创建时快照。
- 修改结算代付方、计费方式或合约期间，只影响保存后的新账务周期和新业务，不追溯改写已经生成的账单。
- 修改合约类型时，不自动删除既有配额、车辆绑定、订单或账单；后续新业务按照修改后的合约类型执行。
- 合约参与未执行转移计划时，修改实际用车企业会使来源和目标企业不一致，系统必须阻止保存并提示先取消转移计划。修改来源合约结束日期后，应重新计算预约转移执行时间；修改目标合约生效时间或总配额后，必须重新校验计划执行时间和预留配额，不满足时阻止保存。
- 所有编辑操作均保存操作人、操作时间、修改前数据和修改后数据。

点击“保存修改”后必须二次确认。生效中或即将到期合约的确认文案须明确：新资料只用于保存后的业务，既有订单、账单、实际生效时间和历史记录不会改写。

## 5. 正式合约生效方式

正式合约新增“生效方式”，包括“立即生效”和“合约期生效”。

### 5.1 时间字段定义

- 合约开始日期、合约结束日期：用于确定正式收费期间、计费周期和合约到期时间。
- 生效时间：用于确定企业端何时可看到并使用合约配额、何时可以绑定和上架车辆，以及该合约何时具备接收即时转移的条件。
- 生效时间与合约开始日期必须分别保存，不得使用同一个字段。
- 时间统一使用企业所属时区判断；台湾企业默认使用 `Asia/Taipei`。合约开始日生效统一按该时区当天 `00:00` 执行。

例如：合约期间为 2026-09-01 至 2026-09-30，选择在 2026-08-15 立即生效，则 2026-08-15 至 2026-08-31 为赠送期，2026-09-01 起进入正式收费期间。

### 5.2 立即生效

- 用户提交并成功建立正式合约时，生效时间记录为实际提交成功时间，合约状态直接变为“生效中”。
- 生效时间早于合约开始日期时，两者之间为赠送期。
- 赠送期内企业端可以查看合约和配额，可以分配分公司配额、绑定车辆、上架车辆并创建公务车预约。
- 赠送期不产生正式合约的月缴、年缴或其他合约基础费用，但车辆使用和预约记录仍正常保存。
- 赠送期不延长合约结束日期。合约仍在原设定的结束日期到期。

### 5.3 合约期生效

- 合约开始日期晚于当前时间时，生效时间为合约开始日 `00:00`，建立后的状态为“待生效”。
- 待生效阶段列表展示计划生效时间并标注“预计”；自动生效成功后写入实际生效时间。
- 到达生效时间后，系统自动将状态改为“生效中”，无需营运人员再次操作。
- 合约开始日期等于或早于当前日期时，不允许回溯生效；实际生效时间记录为提交成功时间，并直接进入“生效中”。
- 待生效期间企业端不显示为可用合约，不允许分配配额、绑定车辆、上架车辆或用于新预约。
- 合约期生效不产生赠送期。

### 5.4 编辑与状态

- 正式合约生效前允许修改生效方式和合约开始日期，保存后重新计算生效时间。
- 正式合约进入生效中或即将到期后，仍可修改生效方式和合约开始日期，但已经写入的实际生效时间不得改写；赠送期按最新开始日期与原实际生效时间重新计算。
- 待生效合约允许撤销或删除；删除后企业端不可见，且不执行后续自动生效。

## 6. 合约转移

### 6.1 适用场景与入口

合约转移用于把来源合约下指定车辆改绑到另一份合约。适用于试用转正式、旧正式合约续接新正式合约，以及同一企业其他车辆换约场景。用户只选择车辆，系统自动处理目标合约对应分公司的配额，来源合约原分公司配额保持不变。

支持两个入口：页面右上角“合约转移任务 → 新增转移任务”，以及来源合约“更多 → 转移至其他合约”。后者满足以下条件即显示，并预填来源合约：

- 来源合约状态为生效中、即将到期，或已过期；
- 来源合约仍有绑定车辆。

满足来源条件即显示入口，不因当前缺少目标合约而隐藏。进入弹窗后，目标合约必须与来源合约属于同一实际用车企业、不是来源合约本身，状态为生效中、即将到期或待生效。选择后根据所选车辆所属分公司校验承接容量和执行时有效性，容量不足或没有候选时提示原因，不能提交；不能仅凭目标待分配配额为零就排除仍有对应分公司空闲配额的合约。

转移功能不负责建立目标合约。试用转正式时，应先建立正式合约，再从试用合约发起转移。

### 6.2 转移范围与校验

营运人员选择目标合约后，系统按来源分公司展示已绑定车辆。用户按分公司选择需要转移的具体车辆，默认全选；不提供转移配额输入。未选择车辆继续绑定来源合约。

计算规则：

- `目标分公司空闲配额 = 目标分公司已分配配额 - 已绑定车辆数 - 已被其他转入计划预留的车辆数`；
- `目标合约待分配配额 = 目标总配额 - 目标已分配配额 - 已被转入计划预留的新增配额`；
- `本次需新增分公司配额 = max（0，分公司本次转移车辆数 - 目标分公司空闲配额）`；
- `允许提交 = 本次转移车辆数 > 0 AND 各分公司需新增配额合计 <= 目标合约待分配配额`。

系统优先使用目标合约同一分公司的空闲配额；不足部分自动从目标合约待分配配额补入该分公司。目标不存在该分公司分配记录时自动建立。分公司必须使用唯一 ID 匹配，不能按名称匹配或覆盖既有分配。

### 6.3 转移结果

转移执行成功后一次性完成：

1. 来源合约原分公司配额保持不变；
2. 所选车辆从来源合约解绑并绑定到目标合约；
3. 目标分公司现有空闲配额优先承接车辆，不足部分自动增加分公司配额；
4. 未选择车辆继续绑定来源合约；
5. 来源和目标合约的总配额均不改变；
6. 来源合约不因转移自动终止，状态和有效期保持原值。

转移只改变车辆的合约绑定，不改变车辆资产归属分公司、所在据点、业务状态和既有预约。车辆能否继续上架仍按目标合约有效性及原车辆业务规则判断。

### 6.4 转移时间

转移方式包括：

| 方式 | 使用条件 | 执行规则 |
| --- | --- | --- |
| 立即转移 | 目标合约已经生效 | 确认后立即校验并执行，不终止来源合约 |
| 来源合约到期时转移 | 计算出的执行时间晚于当前时间 | 保存预约计划并立即预留目标合约车辆承接容量 |

到期转移的执行时间按以下规则计算：

`计划执行时间 = max（来源合约结束次日 00:00，目标合约实际或计划生效时间）`。

- 计划执行时间已经到达时，不允许继续保存“到期时转移”，应改用“立即转移”。
- 预约计划建立后，来源合约配额和车辆仍可继续使用，直到计划实际执行。
- 计划选中的车辆可以继续预约和执行既有订单，但在计划执行、编辑或取消前，不允许解绑来源合约、改绑其他合约或调拨资产归属分公司。
- 目标合约按分公司预留现有空闲配额，并预留不足部分所需的待分配配额；预留容量不能再用于新车辆绑定或其他转移计划。
- 同一来源合约同一时间只允许存在一条待执行任务。任务列表“编辑”和合约“转移至其他合约”进入同一弹窗；来源合约不可更换，目标、车辆及转移时间可修改。新建时选中了已有待执行任务的来源合约，应提示编辑原任务，不能新增第二条。
- 修改提交时，先在计算中排除本任务的旧预留并校验新内容，校验通过后在同一事务内替换任务和预留。不能先实际释放旧预留；关闭弹窗、取消确认、请求失败或校验失败时，旧任务与预留保持不变。
- 取消计划后，目标合约预留容量立即释放，来源合约不发生变更。
- 一个目标合约可以接收多条转移计划，但全部计划不得重复占用同一分公司空闲配额，新增配额预留总和不得超过目标合约待分配配额。

来源到期与转移任务发生在同一时间点时，系统先执行合约转移，再对仍绑定来源合约的车辆执行到期强制下架。若目标合约生效时间晚于来源到期时间，未转移前来源车辆按到期规则下架；后续转移成功只改绑合约，不自动恢复上架。

### 6.5 执行一致性

- 立即转移和预约计划执行均必须在同一事务内完成目标分公司配额补足、目标预留容量释放和车辆改绑；任一步失败时全部回滚，来源分公司配额不修改。
- 预约计划执行前必须重新校验车辆当前绑定合约、目标合约状态和目标预留容量。
- 预约计划中的车辆在执行前已解绑、调拨或改绑时，整条计划执行失败，不允许跳过异常车辆后部分成功。
- 执行期间锁定本次涉及的来源合约、目标合约、分公司配额和车辆绑定记录，完成或回滚后释放。
- 每次转移使用唯一幂等键；定时任务重试不得重复扣减配额或重复改绑车辆。

### 6.6 订单与账单

- 已创建预约和执行中订单继续使用创建时保存的合约、车辆和费用快照，不因合约转移而改写。
- 转移成功后的新预约、车辆管理和新账单使用目标合约。
- 来源合约已经产生的账单仍归属于来源合约，不迁移到目标合约。
- 合约转移不自动终止来源合约，也不自动生成退款、补款或账单冲销。

### 6.7 任务管理

任务列表展示来源合约编号及名称、目标合约编号及名称、车辆数、执行时间、状态、操作；按更新时间倒序，支持合约编号或名称搜索、状态筛选，每页5条。未完成时显示预计时间，完成后显示实际执行时间。

新建和编辑复用原转移弹窗布局：顶部来源合约及已绑车辆摘要、整行目标合约选择、分公司汇总表、转移汇总和底部转移时间。独立新增入口先选择来源；合约“更多”进入时直接带入来源。分公司表展示选择、分公司、来源已绑车辆、已选转移车辆及转移后来源剩余车辆，不展开为逐车大列表。点击分公司的“已选车辆”打开选车小弹窗，支持车牌搜索、逐辆选择及全选搜索结果；确认后回填分公司选择数量，取消不改变原选择，筛选不清除已选车辆。不恢复手工填写转移配额。

新增和编辑时同时只读展示来源总配额、来源已分配配额，并在分公司表保留来源配额列。目标选择下方用紧凑文字展示目标总配额、已分配及待分配可用配额；待分配可用数已扣除其他待执行任务预留的新增配额，编辑当前任务时不重复扣除自身预留。表格下方仅以一行文字展示本次转移车辆数、使用目标既有配额数和需新增配额数，不使用大块彩色汇总卡片。配额展示不改变来源配额保留、目标按需补足的规则；已完成及已取消任务不使用合约当前配额冒充历史配额。

| 状态 | 进入条件 | 可用操作 |
| --- | --- | --- |
| 待执行 | 到期任务保存成功并完成容量预留 | 编辑、取消 |
| 已完成 | 立即转移或到期任务执行事务成功提交 | 查看，只读 |
| 执行失败 | 到期执行未通过校验或事务失败，未发生任何部分转移 | 处理、取消；显示失败原因 |
| 已取消 | 用户确认取消待执行或失败任务 | 查看，只读 |

- 不设置“执行中”业务状态。后台仍须使用任务版本、幂等键及数据库锁，防止执行与编辑、取消竞争；提交按钮的加载效果不属于任务状态。
- 立即转移校验或请求失败时保持弹窗和原任务不变，不创建已完成记录；成功后直接生成已完成任务。
- 待执行任务成功后直接变为已完成；失败后释放全部目标预留容量，不修改来源分公司配额及车辆绑定。
- 失败任务点击“处理”打开同一弹窗，可调整目标、车辆和时间后提交；到期时间已过必须选择立即转移。仍满足未来执行条件的可重新保存为待执行，并重新预留容量。保留原失败及修改审计记录。
- 编辑失败任务时，已不再属于来源合约的车辆从当前待选范围移除，明确提示管理员重新确认；历史失败记录仍保留原车辆快照。
- 取消须二次确认；待执行任务取消时释放预留，失败任务取消不重复释放。已完成、已取消任务保留合约及车辆快照，即使合约后续删除也可查看。
- 后端定时服务负责到期执行，不依赖用户是否打开页面。原型只模拟页面打开期间的任务执行，不具备关闭页面后继续执行或刷新后保留任务的能力。

## 7. 异常处理

- 目标容量不足：阻止提交，并显示目标可承接车辆数和本次转移车辆数。
- 目标未生效：不允许立即转移；可在计划执行时间晚于当前时间时建立到期转移计划。
- 企业不一致：来源与目标实际用车企业不一致时，不展示为可选目标并拒绝接口提交。
- 计划期间数据变化：若车辆绑定、目标状态或企业归属不再满足条件，计划执行失败并通知营运人员，不进行部分转移。
- 合约删除或中止：存在未执行转移计划时，不允许删除相关来源或目标合约；来源或目标被中止、作废时，计划标记失败并释放目标预留配额。
- 重复提交：同一幂等键返回原执行结果；同一来源合约已存在未执行计划时，不允许新建第二条计划，只能编辑或取消原计划。
- 自动执行失败：计划状态改为失败，记录失败原因并通知营运人员；重试前重新执行完整校验。

## 8. 数据记录

合约保留以下生效字段：

- `effectMode`：`IMMEDIATE` 立即生效、`CONTRACT_START` 合约期生效；
- `scheduledEffectiveAt`：计划生效时间；
- `effectiveAt`：实际生效时间，待生效阶段为空；
- `contractStartDate`：正式收费开始日期；
- `contractEndDate`：正式收费结束日期；
- `reservedQuota`：作为目标合约时，为未执行车辆转入计划预留的新增分公司配额总数。

新增合约转移记录，至少包含：

- `transferId`：转移记录编号及幂等键；
- `sourceContractId`、`targetContractId`：来源和目标合约编号；
- `transferMode`：`IMMEDIATE`、`SOURCE_EXPIRE`；
- `scheduledAt`、`executedAt`：计划和实际执行时间；
- `status`：`PENDING` 待执行、`COMPLETED` 已完成、`FAILED` 执行失败、`CANCELLED` 已取消；
- `totalVehicles`：本次转移车辆总数；
- `totalQuotaIncrease`：目标合约需要新增的分公司配额总数；
- `details`：各分公司的车辆编号、使用目标既有空闲配额数及新增配额数；
- `failureReason`：失败原因；
- `operatorId`、`createdAt`、`updatedAt`：操作审计资料。
- `version`：任务版本号，用于拒绝过期页面覆盖已执行、已取消或被其他用户修改的任务；
- `requestId`：每次新增或修改提交的唯一请求号，同一次请求重试保持不变；
- 合约编号、名称及车辆、分公司快照：用于已完成、失败和取消任务的历史查看，不随当前资料覆盖。

来源与目标合约不建立一对一前后继限制。一份来源合约可以先后产生多条转移记录，一份目标合约也可以承接多个来源合约。

## 9. 验收标准

1. 生效中、即将到期及仍有资源的已过期合约可进入“转移至其他合约”；试用和正式合约使用同一入口。
2. 生效中且有绑定车辆的合约始终显示“转移至其他合约”；没有可用目标时进入弹窗显示提示但不能提交。目标只允许同一企业、状态为生效中、即将到期或待生效且执行时有效、容量足够的合约。
3. 页面按分公司展示来源车辆，只允许选择车辆，不显示转移配额输入。
4. 系统优先使用目标同一分公司空闲配额，不足部分从目标待分配配额自动补足；来源分公司原配额保持不变，目标既有分配不被覆盖。
5. 立即转移只允许选择已生效目标；成功后来源和目标总配额不变，所选车辆正确改绑，目标分公司配额按需补足。
6. 立即转移后来源合约不终止，未选择车辆及来源分公司配额不变化。
7. 到期转移保存后，目标现有空闲配额和待分配配额按车辆数正确预留，来源资源在执行前不变化。
8. 已有计划仍从“转移至其他合约”进入原弹窗修改；弹窗可取消计划，修改不会重复占用容量，取消后目标预留容量正确释放。
9. 待执行任务的来源合约显示“有转出任务”，目标合约显示“有转入任务”；完成或取消后移除对应提醒，失败改为“转移失败”并保留至处理完成或取消。
10. 到期任务先执行转移，再下架仍留在到期来源合约的车辆；任一步失败时不产生部分转移。
11. 既有预约、执行中订单和历史账单不被改写，新业务使用转移后的目标合约。
12. 存在未执行转移计划的来源或目标合约不能中止或删除；作废或数据变化导致计划失效时记录失败原因并释放预留容量。
13. 草稿、待客户支付、待生效、生效中和即将到期合约均可修改全部人工录入资料；合约编号、实际生效时间、转移记录、企业单价和审计记录不可直接修改。
14. 编辑目标合约时，总配额不得低于已分配配额与转移计划预留新增配额之和；修改企业或时间导致计划失效时阻止保存。
15. 合约金额列表不显示人民币符号。
16. 待生效和生效中合约均显示“中止合约”和“删除合约”；点击删除后出现二次确认。待生效合约取消计划生效，生效中合约解除当前分公司配额和车辆绑定，删除后营运端和企业端均不再显示，历史订单、账单和审计记录继续保留。
17. 新增正式合约可选择立即生效或合约期生效，列表分别展示合约期间和生效时间。
18. 立即生效早于合约开始日期时正确计算赠送天数，赠送期不计合约基础费用且不延长结束日期。
19. 合约期生效的未来合约显示为待生效，到达生效时间后自动进入生效中。
20. 新增或编辑合约时不显示单车计费单价输入；合约金额按实际用车企业已配置单价计算，企业未配置对应单价时不能保存。
21. 页面可统一查看所有合约操作记录；立即转移写入历史记录及已完成任务，但不显示待执行转入、转出提醒。
22. 独立任务入口与合约“更多”入口共用同一弹窗；任务列表可筛选、分页，合约提醒可跳入对应任务列表。
23. 状态仅包含待执行、已完成、执行失败、已取消。失败可处理或取消，完成及取消只读；任务执行与修改竞争时不得发生重复转移。
24. 编辑校验失败、返回或取消确认不改变旧任务及预留。失败任务取消后消除失败提醒，已完成任务在关联合约删除后仍可查看快照。
