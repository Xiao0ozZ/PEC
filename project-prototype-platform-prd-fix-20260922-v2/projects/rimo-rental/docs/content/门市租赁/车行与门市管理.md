## 1. 功能定位

车行、门市和据点按以下层级管理：

```text
车行 -> 门市 -> 据点
```

| 对象 | 业务职责 |
| --- | --- |
| 车行 | 车辆资产归属、同车行调度边界、结算与营运组织上层归属。 |
| 门市 | 客户面对的门店、柜台营业、人工交还车和门店作业管理。 |
| 据点 | 车辆实际停放、取还车定位、车位、电子围栏及业务模式履约能力。 |

营运端分别提供“车行管理”“门市管理”“服务据点管理”三个页面。服务据点页面左侧车行 / 门市树仅用于筛选范围，不允许在该页面新增或编辑车行、门市。

## 2. 数据关系与字段归属

1. 一个车行可以建立多个门市。
2. 一个门市只能属于一个车行，可以建立多个据点。
3. 一个据点只能属于一个门市。
4. 门市建立后不得直接变更所属车行；确需变更时按组织迁移处理，并单独校验车辆、未完成订单、价格范围和结算归属。

| 配置项 | 归属对象 |
| --- | --- |
| 法人名称、统一编号、车行联系人、车行状态 | 车行 |
| 柜台服务时间、人工交车、人工验车、门市租车营业状态 | 门市 |
| 地址、经纬度、电子围栏、进出方式、总车位、停车费 | 据点 |
| 同站租还、甲租乙还、门市租车、24 小时自助、公务用车能力 | 据点服务能力 |
| 24 小时自助取还方式、是否允许夜间还车 | 据点的 24 小时自助服务能力 |

柜台服务时间、人工交车和人工验车不得在多个据点重复配置。门市租车的据点服务能力只表示该据点可作为门市租车的备车、停放、整备和归还登记位置。

## 3. 车行管理

### 3.1 基础字段

| 字段 | 规则 |
| --- | --- |
| 车行编号 | 必填，租户内唯一，建立后不可修改。 |
| 车行名称 | 必填，租户内不得重复。 |
| 法人名称、统一编号 | 记录签约及结算主体。 |
| 联系人、电话、Email | 用于营运联络。 |
| 状态 | 启用、停用。 |
| 备注 | 非必填。 |

### 3.2 列表与操作

列表展示车行编号与名称、法人资料、门市 / 据点数量、车辆资产数、调度边界、联系人和状态。支持按关键字、状态筛选，并支持导出当前数据范围和筛选结果。

停用车行前必须二次确认。停用后，该车行下的门市、据点和车辆不得参与新预约、新订单、新上架或新调度；既有订单不自动取消、不自动改派，继续按原订单处理。

## 4. 门市管理

### 4.1 基础字段

| 字段 | 规则 |
| --- | --- |
| 所属车行 | 必填，建立后不可直接修改。只能选择启用车行。 |
| 门市编号 | 必填，租户内唯一，建立后不可修改。 |
| 门市名称 | 必填。 |
| 门市地址 | 用于客户展示、订单快照和异地还车判断。 |
| 柜台服务时间 | 必填，用于门市租车现场办理时间判断。 |
| 人工交车 | 默认开启。 |
| 人工验车 | 默认开启。 |
| 门市租车营业状态 | 启用、暂停。仅控制门市租车新订单。 |
| 联系人、电话 | 用于门店作业联络。 |
| 门市状态 | 启用、停用。控制该门市整体是否可参与新业务。 |

### 4.2 列表与操作

列表展示门市、所属车行、柜台服务时间、人工作业配置、门市租车营业状态、所属据点数、可履约据点数、当前可营业结果、联系人和门市状态。

支持按关键字、所属车行、门市租车营业状态、门市状态筛选，并支持导出当前数据范围和筛选结果。

门市租车营业状态暂停时，只停止该门市的门市租车新订单，不影响该门市下据点已独立启用的分时租赁、公务用车或 24 小时自助能力。

## 5. 状态判断与联动

### 5.1 门市租车可营业

门市租车可营业必须同时满足：

```text
所属车行启用
AND 门市启用
AND 门市租车营业状态启用
AND 至少存在 1 个已启用据点，其门市租车服务能力为启用
```

任一条件不满足时，该门市不得出现在门市租车的新订单可选范围内。页面应展示具体原因，例如“所属车行停用”“门市租车暂停”或“无可履约据点”。

### 5.2 24 小时自助可用

24 小时自助按具体据点判断：

```text
所属车行启用
AND 所属门市启用
AND 据点启用
AND 据点的 24 小时自助服务能力启用
```

24 小时自助不受门市租车营业状态影响，但仍受车行和门市整体状态影响。

### 5.3 上下级停用

1. 停用车行或门市时，不自动改写下级对象自身保存的状态。
2. 上级停用期间，下级即使自身为启用，也不得参与新业务。
3. 上级重新启用后，系统重新按下级自身状态和服务能力判断，不自动把已暂停或停用的下级改为启用。
4. 已创建订单保留原门市、据点和快照，不自动取消、改派或迁移。

## 6. 权限与数据范围

实际可见和可操作范围由“数据范围 + 功能权限”共同决定。数据范围控制账号能看到哪些车行、门市；功能权限控制账号能否新增、编辑、启停或导出。

| 权限 | 允许操作 |
| --- | --- |
| 车行查看 | 查看数据范围内的车行。 |
| 车行维护 | 新增、编辑、启停车行。 |
| 门市查看 | 查看数据范围内的门市。 |
| 门市维护 | 新增、编辑、启停门市，调整门市租车营业状态。 |
| 车行 / 门市导出 | 按当前数据范围和筛选条件导出。 |

数据范围规则：

1. 租户级：可查看租户内全部车行和门市；具备对应维护权限时，可新增、编辑和启停。
2. 车行级：车行页面只展示当前车行；门市页面只展示当前车行下的门市。不得新增车行；具备门市维护权限时，可在当前车行下新增和维护门市，所属车行固定且不可选择其他车行。
3. 门市级：门市页面只展示当前门市；不得新增门市，只能在具备门市维护权限时编辑或启停当前门市。
4. 只读：按账号数据范围展示数据，但隐藏新增、编辑和启停入口；导出是否开放由独立导出权限决定。
5. 卡片统计、列表总数、分页、筛选项和导出结果必须基于权限过滤后的数据计算，不得统计或导出数据范围外的记录。
6. 门市级账号不得查看或操作其他门市；仅有据点服务模式权限的账号不得修改车行或门市资料。

前端隐藏操作入口只用于界面控制。查询、新增、编辑、启停和导出接口必须在后端重新校验账号数据范围与功能权限；越权请求直接拒绝，不得依赖前端传入的车行或门市编号判断权限。

新增、编辑、启用、停用车行或门市，以及调整门市租车营业状态，必须记录操作人、操作时间、变更前后值和原因。

## 7. 开发校验

1. 新增门市时，后端必须重新校验所属车行存在且启用。
2. 停用车行或门市时，后端返回未完成订单数量供前端确认，但不阻止停用。
3. 新订单、车辆上架、调度、APP 据点查询均必须在后端重新校验完整上级状态，不能只依赖前端隐藏选项。
4. 车行、门市、据点名称和状态必须保存到订单快照；历史订单不得通过当前主数据反推。
5. 门市租车的跨门市费用和调度边界按门市判断；本期仍只允许同车行范围，不支持跨车行调度。

## 8. 原型与验收

对应营运端原型：

- `02_原型和PRD/原型/营运端/rental_companies.html`
- `02_原型和PRD/原型/营运端/stores.html`
- `02_原型和PRD/原型/营运端/stations.html`

车行和门市原型右下角提供“权限演示”，用于切换租户级、车行级、门市级和只读情景。该控件仅用于原型演示；正式系统按登录账号权限自动计算，不向用户提供手动切换入口。

验收重点：

1. 三个页面职责和编辑入口不重复。
2. 门市列表可明确识别可营业、暂停和无可履约据点。
3. 停用上级后，下级不参与新业务，但自身状态和既有订单不被改写。
4. 重新启用上级后，仍按下级原状态恢复判断。
5. 门市租车配置不再出现在据点编辑窗口中。
6. 切换不同权限情景后，卡片、列表、分页、筛选和导出范围同步变化。
7. 无维护权限时不显示新增、编辑入口，状态开关不可操作；直接调用接口同样被后端拒绝。
